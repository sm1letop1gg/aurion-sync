# Aurion Sync

> **Важно:** Aurion Sync — не официальный проект сервера, а разработка от комьюнити. Главный разработчик — **Sm1Le**.

Discord-бот переносит роли, цвета ролей, участников ролей и серверные ники с основного сервера Aurion (`1509633054451175575`) на другие серверы. Пользователи сопоставляются исключительно по постоянному Discord ID. Актуальные данные хранятся в SQLite и доступны сайту через защищённый REST API.

## Как работает `/sync`

1. Администратор запускает `/sync` на целевом сервере и выбирает режим:
   - **Полная синхронизация** — разрешённые роли и серверные ники;
   - **Только никнеймы** — роли не создаются, не выдаются и не снимаются.
2. Бот читает актуальные роли и всех участников основного и целевого серверов.
3. Бот показывает предварительный расчёт и кнопки подтверждения/отмены. Подтверждение действует 2 минуты и доступно только вызвавшему команду администратору.
4. После подтверждения бот:
   - в полном режиме создаёт отсутствующие разрешённые роли с исходными названиями и цветами;
   - обновляет название/цвет ранее связанной роли;
   - находит общих участников по Discord ID;
   - выдаёт недостающие и снимает лишние синхронизируемые роли;
   - переносит установленный на основном сервере ник;
   - оставляет текущий целевой ник без изменений, если исходный ник не установлен;
   - показывает итоговый отчёт и список неудачных действий.

Повторный запуск не создаёт дубликаты: в `data/sync-state.json` хранится связь `целевой сервер + ID исходной роли → ID созданной роли`. Если связи ещё нет, роль ищется по точному названию.

Все остальные роли не создаются, не обновляются, не выдаются и не снимаются. Участник с ролью `1509633054451175583` полностью игнорируется во всех режимах: бот не меняет его роли и ник.

После успешного ручного запуска сервер и выбранный режим сохраняются. Каждые 15 минут бот повторно читает роли и участников основного сервера и обновляет уже синхронизированные серверы. При входе нового участника на такой сервер бот сразу применяет сохранённый режим: в полном режиме выдаёт разрешённые роли и переносит ник, а в режиме никнеймов меняет только ник.

Во всех видимых ответах, отчётах, ошибках, описании `/sync` и Discord-статусе бот сообщает, что это не официальный проект сервера, а разработка от комьюнити, главный разработчик которой — Sm1Le.

Управляемые интеграциями роли, роли ботов, Booster-роли и `@everyone` не копируются. Права ролей намеренно не переносятся — по ТЗ синхронизируются название и цвет, а автоматическое копирование административных разрешений было бы небезопасно.

## Настройка Discord

В [Discord Developer Portal](https://discord.com/developers/applications):

1. Создайте приложение и Bot User.
2. На странице **Bot → Privileged Gateway Intents** включите **Server Members Intent**.
3. Добавьте одного и того же бота на основной сервер Aurion и на целевые серверы со scope `bot` и `applications.commands`.
4. На целевых серверах выдайте боту **Manage Nicknames**; для полной синхронизации также требуется **Manage Roles**.
5. Поднимите собственную роль бота выше всех ролей и участников, которыми он должен управлять.

Discord не позволит изменить владельца сервера, самого бота или участника с равной/более высокой ролью. Такие случаи попадут в отчёт как ошибки.

## Установка и запуск

Требуется Node.js 22.13 или новее. Внешних npm-зависимостей нет.

```powershell
Copy-Item .env.example .env
```

Заполните `.env`:

```env
DISCORD_TOKEN=токен_бота
DISCORD_CLIENT_ID=id_приложения
SOURCE_GUILD_ID=1509633054451175575
DATABASE_FILE=./data/aurion-sync.sqlite
STATE_FILE=./data/sync-state.json
API_HOST=127.0.0.1
API_PORT=3000
WEBSITE_API_TOKEN=случайный_секрет_длиной_не_менее_32_символов
WEBSITE_ORIGIN=https://адрес-вашего-сайта.example
```

`STATE_FILE` нужен только для однократного автоматического импорта старого JSON. После успешного импорта все новые данные записываются только в SQLite. Случайный API-токен можно создать командой:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Затем:

```powershell
npm run build
npm test
npm run register
npm start
```

`npm run register` регистрирует глобальную команду `/sync`. После запуска оставьте процесс работающим.

## База данных

`data/aurion-sync.sqlite` содержит:

- роли основного сервера, их названия, цвета и признаки managed;
- Discord ID участников, серверные никнеймы и связи участников с ролями;
- связи исходных ролей с ролями каждого целевого сервера;
- автоматически синхронизируемые серверы и выбранный для каждого режим;
- последний отчёт синхронизации каждого целевого сервера;
- настройки политики синхронизации и время последнего снимка.

SQLite работает в режиме WAL. Файлы `.sqlite`, `.sqlite-wal`, `.sqlite-shm`, старый state-файл и `.env` исключены из Git. База содержит персональные данные участников: не публикуйте её, ограничьте доступ и включите резервное копирование.

## API для сайта

API запускается вместе с ботом. Каждый ответ содержит пометку, что Aurion Sync не является официальным проектом сервера, а главный разработчик — Sm1Le.

- `GET /api/v1/health` — проверка доступности, токен не требуется;
- `GET /api/v1/roles` — список девяти разрешённых ролей;
- `GET /api/v1/members?limit=250&after=DISCORD_ID` — страница участников с Discord ID, никнеймами и разрешёнными ролями.

Для защищённых маршрутов передавайте заголовок:

```http
Authorization: Bearer WEBSITE_API_TOKEN
```

Пример запроса:

```powershell
Invoke-RestMethod `
  -Uri "http://127.0.0.1:3000/api/v1/members?limit=250" `
  -Headers @{ Authorization = "Bearer $env:WEBSITE_API_TOKEN" }
```

Участники с ролью `1509633054451175583`, боты и роли вне разрешённого списка через API не возвращаются. Максимальный размер страницы — 1000 участников; значение `nextAfter` используется для следующего запроса.

По умолчанию API доступен только локально на `127.0.0.1`. Если сайт находится на другом сервере, задайте `API_HOST=0.0.0.0`, укажите точный origin сайта в `WEBSITE_ORIGIN` и публикуйте API только через HTTPS reverse proxy. Не помещайте `WEBSITE_API_TOKEN` в открытый клиентский JavaScript: запросы к Aurion Sync должен выполнять сервер сайта.
